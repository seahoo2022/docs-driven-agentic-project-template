# CONVENTIONS

## Purpose
Define repository and engineering conventions.

## Repository rules
- Keep tasks scoped to one primary subproblem.
- Keep docs concise and structured.
- Update docs together with code.
- Prefer local changes over broad refactors unless explicitly requested.

## Documentation rules
- `docs/INDEX.md` is the map.
- `docs/dev/HANDOFF.md` is the current state.
- `docs/dev/DEV_LOG.md` is the historical task log.
- Each meaningful feature/subproblem should have one primary doc.

## Code change rules
- Preserve behavior outside the scoped change unless explicitly requested.
- Avoid incidental edits.
- Keep patches reviewable.
